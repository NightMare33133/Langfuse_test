## 核心原则

**每条查询必须满足：**
1. **单一概念** — 只对应一个明确的、可在候选目录中定位的事实
2. **单一候选** — 必须从候选目录中选择一个 candidate_id
3. **单一目标字段** — 每题只围绕一个 target_field 出题
4. **无需聚合** — 不需要从多个候选拼凑信息
5. **无需推理** — 金标准证据是单元格中的直接值，不需要归纳、推导、计算公式结果或对比
6. **可为近义改写** — 查询可以与单元格原文措辞不同，但只能是单一概念的近义改写

## query（检索查询）规范

**query 必须是短检索查询，可为词、词组、短语或单一检索意图：**
- 可以是：名词、名词短语、动宾短语、"修饰语+核心概念"
- 可以与原文措辞不同（近义改写）
- 不得是问句 — 禁止出现问号（？）
- 禁止问答或推理导向表达 — 不得包含"什么/为何/为什么/如何/是否/哪些/请分析/请说明/分别"等词
- 不得引入表中不存在的信息
- 可以是自然的短检索意图，例如"某需求的总成本""某需求的前端工程师工作量"

## 候选目录选择规则

下方"候选目录"由本地程序从电子表格结构中自动生成。**你只能从候选目录中选择 candidate_id，不得自行创造 anchor_range、字段或数值。**

每条查询必须：
1. 从候选目录中选择一个 `candidate_id`
2. `target_field_label` 必须与该候选的 `target_field.label` **完全一致**
3. 每题只能围绕一个 `target_field` 出题
4. 查询可以是自然的短检索意图，不得生成聚合、比较、推导类查询

## 输出格式

请严格输出一个 JSON 数组，不要包含任何其他文字。每个元素包含以下字段：

```json
[
  {
    "candidate_id": "从候选目录中选择的 candidate_id",
    "question": "短检索查询（词/词组/短语，非问句）",
    "target_field_label": "与候选目录中 target_field.label 完全一致",
    "difficulty": "事实/基础",
    "topic": "查询涉及的具体知识点"

]
```

**重要规则**：
- `candidate_id` 必须是候选目录中存在的值，不得自造
- `target_field_label` 必须与该候选的 `target_field.label` 完全一致
- 不要输出 `reference_answer` 字段，它将由本地程序自动生成
- 如果表格内容不适合生成 {num_questions} 条检索查询，请减少实际生成数量即可
